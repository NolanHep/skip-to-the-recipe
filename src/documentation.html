Getting Started

Welcome to the official Skip To The Recipe API documentation! This guide will help you understand how to use our API effectively. Our API is designed to be simple and intuitive, allowing you to easily integrate our features into your applications.

To get started, you can check out our endpoints and see how to make requests and handle responses.

Endpoints

Gather recipe name, image, ingredients, and directions from recipe links

Visit

Recipe
POST /api/v1/recipe

Our recipe endpoint lets you integrate our recipe-fetching feature into your next project. With this powerful tool, you can automatically gather ingredients and instructions from recipe links—perfect for creating a streamlined user experience.

Request

Making a request is as simple as placing the recipe URL in the url query parameter and setting the request method to post

URL
https://skip-to-the-recipe.vercel.app/api/v1/recipe?url={Recipe URL}

Response

Bellow you can see an example of a response containing the recipe name, image, ingredients and directions. There are also a few errors you may encounter instead such as missing url parameter and invalid url.

Keep in mind that the image parameter sometimes isn't in the response, because no image was found.

Making a Request

Making a requets to our API is quick, simple, and downright easy. Each endpoint has its own request method, URl, and parameters, so just follow the instructions for your selected ednpoint.

Handling Responses

When you make a request to our API, you will receive a response. The response will contain the data you requested, along with any relevant metadata.

At the moment, all our endpoints respond in JSON format, which is easy to parse and work with in most programming languages.

Receiving Errors

Instead of a response with data, you could receive an error, which are also send in JSON format. The message parameter provides you with a easy and simple understanding of what happend alongside the error parameter. The error parameter gives you more detailed of a description about the problem, but note that this parameter isn't always sent, meaning it shouldn't be used to rely on detecting an error. It's also good practice to not rely on the message parameter, nor any parameter for that mater if possible.
